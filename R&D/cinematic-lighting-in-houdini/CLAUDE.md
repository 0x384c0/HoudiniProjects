# CLAUDE.md

Houdini R&D project: cinematic lighting study, rendered with both Karma XPU and Arnold GPU. Shared rules (storage, `$HIP_CACHE`, OCIO, tools, Karma vs Arnold gotchas, headless workflow, git, conventions) are in the repo-root `CLAUDE.md` (`../../CLAUDE.md`).

## Layout

- `assets.hip` — main scene, one parallel `/stage` network per asset: shader-ball material lookdev, cruiser component + lookdev, bomber lookdev (all below). Source assets under `$HIP_CACHE/TMP/assets/<asset>`.
- `hda/matgen_mtlx.hda` — LOP HDA "MaterialX Texture Material Generator". Built from `scripts/matgen_mtlx.py` (its PythonModule) by `hython scripts/build_matgen_hda.py`; edit the .py and rebuild, don't edit the HDA by hand. `assets.hip` loads it from `$HIP/hda/`.

## Material generator (matgen_mtlx)

- Stateless: nothing is stored in the .hip; the output depends only on the node's parameters and the files on disk. Cache it downstream with a File Cache LOP.
- Scans a texture folder, parses names into (material, channel) with editable regex token patterns (the LAST channel token in the name is the channel, text before it is the material), collapses UDIM tiles to `<UDIM>`, and outputs one MaterialX Standard Surface per material at `/materials/<name>` (Karma XPU + Arnold). Scan results are cached in memory per parameter values + folder mtime; "Rescan Folder" forces it and fills the Report.
- Internals (locked HDA contents): `empty` → `begin` (Begin Context Options Block) → `materials` (Material Library with ONE `template` material) → `prune` (Python LOP) → `foreach` (For Each, iterate over strings = `material_names()`; the loop body goes on its THIRD input, the HDA input on the first). Material path, image files and colorspaces are Python expressions reading `hou.contextOption('ITERATIONVALUE')`; `prune` removes shader prims / material inputs / connections of channels the texture set doesn't have (branch nodes are named `<channel>_*`).
- Template look: colour = image → mtlxrange → mtlxhsvadjust, float = image → mtlxrange, normal = normalmap scale, height = range → displacement. Change it in `build_template()` and rebuild the HDA.
- Why not a VOP `switch` per channel: Houdini exports it to USD as a literal shader node instead of resolving it.
- Expression results aren't variable-expanded like literal parm values, so `chan_file()` expands `$HIP_CACHE` itself.
- Promoted values are Parameter VOPs → `UsdShade.Material` inputs (`basecolor_hsv`, `roughness_outhigh`, `normal_scale`, `emission_weight`, …), editable with Edit Material Properties. Data maps get colorspace `Raw`; colour maps `auto`.
- UV transform (template nodes `uv_*`, shared by all image nodes): material inputs `uv_tiling` (repeats, vector2), `uv_offset`, `uv_rotate` via `mtlxplace2d` (pivot 0.5). Applied per UDIM tile (`tile + mod(place2d(uv - tile), 1)`) so tiling never reads other tiles. MaterialX `place2d` divides UVs by its `scale` (= texture size), so the template feeds it `1 / uv_tiling`.
- "Fill Missing UDIM Tiles" (default on): works around Arnold GPU's red missing-tile shading (root `CLAUDE.md`). Builds `$HIP_CACHE/matgen_udimfill/<material>/<channel>/` with hard links to the real tiles + 4x4 neutral placeholders whenever a channel lacks tiles other channels of that material have (cruiser emissive sets are sparse; ship normal lacks 1049).
- Texture folders have stray `.rat`/`.tx` caches next to the EXRs; the generator prefers `.exr`.

## /stage lookdev network (assets.hip)

`matgen_cruiser` (no input) → `cache_materials` (File Cache, `$HIP_CACHE/usd/cache_materials/v<N>/`, Load from Disk on) → `merge_materials` (+ `material_lookdev`, SideFX shader-ball scene) → `editmaterialproperties1` → `rendergeometrysettings1` → `look_*` (Edit Material Properties per material) → `shaderball_grid` → `lights_off` → `sky_hdri` → `LOOKDEV_OUT`, then two render branches: `arnold_rendersettings1` (GPU) → `renderpass1` → `usdrender_rop1`, and `karmarendersettings` → `renderpass2` → `usdrender_rop2`.
- `cache_materials` loads from disk, so matgen parameter or texture changes only show after "Save to Disk" again (or with Load from Disk off).
- `LOOKDEV_OUT` has no RenderSettings prim; render settings come from the branch nodes. `arnold_rendersettings1` sets camera `/World/Camera`, 1280×720, GPU, and Auto-Tx Path `$HIP_CACHE/tx` (Rendering > Texture; Arnold writes `.tx` there, mirroring the source path, instead of next to textures).
- Python LOP source lives in `scripts/lop_shaderball_grid.py`; push edits into the node with `scripts/apply_lookdev_lops.py` (Python Shell: `exec(open(hou.text.expandString('$HIP/scripts/apply_lookdev_lops.py')).read())`).
- `shaderball_grid` (Python LOP): one shader ball per `/materials/*` prim under `/World/Lookdev/<mat>`, grid layout, frames `/World/Camera` (16:9 aperture). Shader-ball UVs only cover UDIM 1001, so it shifts each ball's `st` onto its material's first base-colour tile (balls are then plain references, not instances). Shader-ball UVs are also inset 0.004 from tile edges so seams don't read neighbour tiles.
- `sky_hdri`: dome with `$HIP_CACHE/TMP/hdri/HDRIHaven_kiara_5_noon_2k.exr` (converted from Houdini's bundled `.rat` with `iconvert`). The HDRI contains the real sun, so no extra sun light.

## Cruiser component (assets.hip)

Source: `$HIP_CACHE/TMP/assets/cruiser/model/_publish/cruiser_mdl_v030.bgeo.sc` (20.4 M polys, prim attrs `path` = 124 parts, `shop_materialpath` = `/mat/<name>`, one material per part; vertex `uv`, `N`) + `cruiser_mdl_v030.mtl` (Blender export; names match the texture sets, plus untextured `glass`, `greeble`, `panels_and_lights`; only `glass` is used).

`componentgeometry1` → `componentmaterial1` (+ `merge_asset_materials` = `matgen_asset` (matgen, prefix `/ASSET/mtl/`) + `materiallibrary1` (hand-made `glass`)) → `componentoutput1` (root `/cruiser`, writes `$HIP_CACHE/usd/assets/cruiser/cruiser.usd`).
- `componentgeometry1/sopnet/geo`: `cruiser_bgeo` → `remove_curves` (1124 open 2-point polys) → `material_scopes` (`s@mtl` from `shop_materialpath`, path → `/<mtl>/<part>`) → `drop_shop_materialpath` → `RENDER` → default output. Proxy: `RENDER` → `delete_small_parts1` → `proxy_reduce` (PolyReduce 5%) → `proxy_cache` (File Cache SOP, `$HIP_CACHE/geo/cruiser_proxy`, ~6 min to rebuild; re-save when the source changes) → `proxy_color` (random hue per `mtl`, stateless) → `PROXY` → proxy output (~1.2 M polys, no material binding, display colour only).
- Material rows in `componentmaterial1`: one per `mtl` value, `/ASSET/geo/render/<mtl>` → `/ASSET/mtl/<mtl>`. Filled by `scripts/assign_component_materials.py` (`assign()`), rerun when the material set changes.
- Cruiser lookdev: `componentoutput1` → `cruiser_camera` (`/cameras/cruiser_cam`, 3/4 view, 35 mm, 16:9 aperture 36×20.25) → `cruiser_sky` (copy of `sky_hdri`) → `CRUISER_OUT` → `cruiser_arnold_settings`/`_pass`/`_rop` (copy of the shader-ball Arnold branch, 1920×1080, dicing camera = cruiser cam) and `cruiser_karma_settings`/`_pass`/`_rop` (XPU). ROPs write `$HIP_CACHE/render/cruiser_{arnold,karma}.$F4.exr`. Full-res stage cook ≈ 2 min / ~21 GB RAM in hython.
- Arnold GPU VRAM (RTX 5060 Ti 16 GB, full ship 1080p): no displacement 11.4 GB; displacement on all parts crashes even at 2 px (VRAM full, CUDA access violation). Fix in render settings only: `cruiser_arnold_subdiv` = `/cruiser/geo/render/panels/plate_*` and `cruiser_arnold_nodisp` (Render Geometry Settings, `arnold:disp_height` 0) on everything else → 53 s, 13.1 GB VRAM. Karma is untouched (displaces everything).
- Displacement re-enabled by the user (`asset_height` after the cache: In High 0.02, scale 1). Arnold dicing in `cruiser_arnold_subdiv`: linear, adaptive edge length 1 px, cap 6, padding 0.6, no autobump = closest to Karma on the isolated panels (catclark/2 px looked blobby; 0.5 px/cap 8 ran out of memory; autobump harsher than Karma). Earlier findings: height maps are 0..0.018, so relief is sub-pixel at shot distance; Karma's extra "panel detail" with displacement on is a dicing artifact (faceted normals), unchanged even at 100x strength; with displacement off Karma and Arnold match. Arnold GPU crashed (CUDA, ~29 GB) with displacement; the mesh also needed `repair_nonmanifold` (PolyDoctor, non-manifold points only: 233k non-manifold edges) for Arnold to subdivide at all.
- `componentoutput1` has Load from Disk on: material/geometry changes reach the lookdev renders only after Save to Disk (Localize is off; textures stay in `$HIP_CACHE`).
- Look edits on `/materials` (lookdev chain) don't apply to `/ASSET/mtl`; the asset materials come from their own matgen instance.
- Cruiser textures: `$HIP_CACHE/TMP/assets/cruiser/text/_publish/v003/2k/` — 411 UDIM EXRs named `cruiser_mdl_v030_<part>_<Map>_<colorspace>.<UDIM>.exr`; BaseColor/Emissive are `_ACES - ACEScg`, Height/Normal/Roughness/Metallic are `_Raw`.

## Bomber lookdev (assets.hip)

Source: Rebelway week-2 published component, extracted from the course `Project Files.rar` (`RBL3/assets/veh/bomber`) to `$HIP_CACHE/TMP/assets/bomber/_publish/`: `bomber.usd` (default prim `/bomber`, Y-up, metres; variant sets `geo` = landing_gear/no_landing_gear, `mtl` = 2k_textures/4k_textures, only 2k textures shipped) → `data/{payload,geo,mtl}_v001.usdc` + `data/textures/` (UDIM EXRs `transport_v020_<part>_<Map>_<cs>`, landing gear `bomber_undercarriage_v004_NEW.001_*`). 8 parts / 8 materials, 1.2 M polys, ~29 m wide.
- Network, parallel to the cruiser one (copied from it, `cruiser` → `bomber` in names/paths): `bomber_ref` (Reference LOP, `/bomber`) → `bomber_camera` (`/cameras/bomber_cam`, same 3/4 angle and lens as the cruiser cam, framed to the bbox) → `bomber_sky` → `BOMBER_OUT` → `bomber_arnold_settings`/`_pass`/`_rop` and `bomber_karma_settings`/`_pass`/`_rop`. ROPs write `$HIP_CACHE/render/bomber_{arnold,karma}.$F4.exr`. No displacement, so no Arnold subdiv/nodisp nodes.
- Materials are the asset's own, not matgen: each has `outputs:arnold:surface` (Arnold shader network) and `outputs:kma:surface` (MaterialX nodegraph `<part>_KM`), so Arnold and Karma render different networks (exception to the MaterialX-only rule; it's a published asset). They reference some textures that don't exist (e.g. GLASS Metallic/Emissive, panels Emissive): Arnold logs `unable to load an image` warnings but the 960×540 test showed no red shading; Karma and Arnold matched (~50 s each).
